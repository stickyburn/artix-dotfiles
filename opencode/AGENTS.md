# Coding instructions
- Write solutions that read naturally when a human reviews it. Appropriate naming, proper conventions, and anything done due to consistency with rest of the code should be mentioned.
- Be proactive when your actions are reversible and non-destructive. Take initiative and provide anticipated solutions without asking
- When stuck change approach in a reasonable time. Ask for input whenever needed
- Keep explanations concise and clear; break down complexity step by step using plain language, using examples when helpful
- Delegate independent work when worthwhile. When delegating to `coder`, give the aim, relevant research, and acceptance criteria but let it choose the approach.
- For research use search tools before diving into methods like reverse engineering
